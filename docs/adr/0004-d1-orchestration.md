# 0004 — Orquestación persistente en D1

2026-11-17. Implementación del stack aprobado; sin colas ni servicios adicionales.

F3-01 añade jobs, attempts, dependencies, activities, checkpoints y recibos de comandos, además de pause_requested en projects. Los inputs de jobs y las aristas publicadas no se editan ni se borran. Las relaciones usan FK compuestas por proyecto; las versiones de checkpoints también. El scheduler puro valida DAG/estados/readiness sin reloj global ni I/O. La selección SQL aplica las mismas condiciones y crea actividad en el mismo batch. JobDto excluye payload, hashes de entrada y tokens de lease.

Crear job es idempotente por proyecto y key UUID, con hash canónico del input y snapshot de respuesta atómico. Repetir con input distinto es conflicto; un reintento de transporte no crea otro trabajo. Dependencias deben existir en el mismo proyecto; el alta incluye todas sus aristas antes de liberar READY. Triggers rechazan ciclos SQL y añadir aristas tras programar. Referencias a versiones incluyen hash; versiones invalidadas/sustituidas no quedan listas.

Defaults reversibles: hasta 16 dependencias, 8 referencias de input, payload 64 KiB, 3 intentos (máximo configurable 10), tick hasta 20 jobs. El lote de migraciones del harness se agrupa de 16 en 16 para reducir IPC; producción/local siguen usando el ledger de Wrangler, sin cambiar SQL ni aplicar migraciones destructivas.

F3-02 completa leases de 90 s, heartbeat y fencing por token de intento; claim exclusivo conservador por proyecto. Cada cambio de job/attempt/actividad/checkpoint ocurre en batch condicional. Un complete repetido del token ganador reproduce el resultado, un token vencido no publica. Reloj y jitter inyectados: backoff base 15 s → 60 s con tope 10 min, Retry-After puede ampliar la espera. Los fallos de autenticación no reintentan automáticamente; reintento explícito conserva intentos previos y concede uno adicional hasta el límite 10.

Antes de una llamada externa el runner debe registrar external_started bajo lease vigente; si no lo consigue, no debe invocar al proveedor. Un timeout o lease vencido con efecto posible queda UNKNOWN/WAITING_RESOURCE sin repetición ciega. La reconciliación acepta rechazo o resultado verificado desde un adaptador servidor (pruebas con fixtures), no desde inputs del navegador. Pausa impide nuevos claims, PAUSING conserva operaciones irreversibles y solo permite pausa segura si no empezó efecto externo. Resume comprueba versiones/dependencias y nunca reactiva STALE.

Existe handler scheduled y coordinador acotado a un proyecto/lease vencido por tick, independiente del browser. Descarta inputs obsoletos al seleccionar proyectos para que no monopolicen la coordinación. No se configura cron cloud ni se despliega; los ticks deben ser invocados por un disparador de servidor autorizado. No ejecuta contenido: los adaptadores se añadirán en F4/F5. Nunca declara proyecto COMPLETED/READY_RENDER solo por terminar los jobs existentes. Los endpoints de agente/pairing siguen en F5; F3-03/04 conectan política y seguimiento.

F3-04 expone comandos de propietario, no de ejecución: inicio requiere DRAFT confirmado y revisión actual, y registra proyecto/job/recibo atómicamente. Pausa/resume/retry mantienen snapshots de comandos y conservan intentos. Revisión exige checkpoint y subject exactos, hash/inputs/parent y última versión; cambia catálogo/checkpoint/job/actividad/recibo en el mismo batch, sin modificar payload aprobado. Si hay derivados activos que requieren invalidación de guion se rechaza hasta F4.

La web reutiliza el shell aprobado. Polling se suspende offline/oculto y descarta respuestas de otra ruta; los formularios conservan su revisión al editar. Un resultado de comando perdido se reintenta con key/payload originales antes de permitir otra acción. Dialog nativo conserva foco/escape. Progreso solo de unidades/jobs registrados; plannedTotal desconocido se mantiene null. Las previews son snapshots privados para revisión, no editores. El presupuesto se formatea sin redondear microunidades de la contabilidad.
